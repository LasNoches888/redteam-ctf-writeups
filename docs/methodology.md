# Методика решения CTF-заданий

Универсальный порядок работы, который подходит для большинства категорий.

## 1. Прочитать условие и понять формат ответа
- Какой формат флага (`flag{…}`, `CTF{…}`)? Сколько очков — подсказка о сложности.
- Что даёт организатор: файл, адрес сервиса, исходники? Есть ли ограничения (запрет сканирования, лимит запросов)?
- **Правила соревнования важнее любого совета**: атакуйте только инфраструктуру задания, не платформу и не других участников.

## 2. Разведка
| Категория | Первые шаги |
|-----------|-------------|
| web | просмотр исходного кода страницы, `robots.txt`, запросы в браузерных DevTools, анализ параметров и cookie |
| crypto | определить тип шифра по виду данных (hex, base64, длина), вспомнить известные слабости |
| forensics | `file`, `strings`, `exiftool`, анализ метаданных, поиск вложенных данных (`binwalk`) |
| reversing | `file`, `strings`, дизассемблер/декомпилятор, поведение под отладчиком |
| pwn | `checksec`, запуск локально, поиск уязвимого ввода |

## 3. Гипотеза → проверка
Запишите гипотезу одной строкой («параметр `q` не экранируется») и найдите самую дешёвую проверку.
Меняйте **одну** вещь за раз.

## 4. Эксплуатация
Автоматизируйте повторяющиеся действия скриптом — он станет частью разбора. Сохраняйте сырые запросы и вывод.

## 5. Флаг и разбор
Сдайте флаг, затем сразу напишите разбор по [`TEMPLATE.md`](../TEMPLATE.md), пока детали свежи:
что дано → как нашли → как использовали → как это исправить.

## Ведение заметок
- Одна заметка на задание: ссылки, гипотезы, команды, тупики. Тупики не менее ценны, чем успехи.
- Все команды — в виде, пригодном для копирования и повторного запуска.
- Секреты и реальные флаги платформ в публичных разборах заменяйте на `REDACTED`, если правила соревнования запрещают публикацию.

## Что нельзя
- Публиковать разборы заданий, если правила соревнования это запрещают (часто — до его окончания).
- Использовать приёмы из CTF против систем, на которые нет разрешения.
