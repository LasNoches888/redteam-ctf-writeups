# XOR одним байтом — crypto — 100 (учебное задание)

> Задание самодельное: исходники в [`challenges/single_byte_xor`](../challenges/single_byte_xor).

## Описание
Дан шифртекст в hex (72 байта) в файле `challenge.hex`:
```
0e323f7a2b2f3339317a3828352d347a3c35227a302f372a297a352c3f287a2e323f7a363b20237a...
```
Известно только, что сообщение — английский текст, зашифрованный XOR с одним байтом, и содержит флаг `flag{...}`.

## Разведка
- Длина 72 байта, читаемого текста в шифртексте нет.
- Шифр с ключом в один байт имеет всего **256 возможных ключей** — перебор тривиален.
- Первые байты шифртекста `0e 32 3f 7a …`. Байт `7a` повторяется между словами часто — в английском тексте чаще всего повторяется пробел (`0x20`).
  `0x7a ^ 0x20 = 0x5a` — это уже подсказка для ключа.

## Эксплуатация
Два способа прийти к ответу.

**1. Угадывание по пробелу.** Самый частый байт в шифртексте — вероятно, зашифрованный пробел. Ключ = `самый_частый_байт ^ 0x20`:
```python
from collections import Counter
ct = bytes.fromhex(open("challenge.hex").read().strip())
most_common = Counter(ct).most_common(1)[0][0]
key = most_common ^ 0x20          # 0x5a
print(bytes(b ^ key for b in ct).decode())
```

**2. Перебор с оценкой читаемости** (`solve.py`): расшифровать всеми 256 ключами и выбрать результат с наибольшей долей
частых английских букв и пробелов.
```
$ python solve.py challenge.hex
ключ 0x5a  оценка  115  The quick brown fox jumps over the lazy dog. flag{demo_single_byte_xor}
ключ 0x5b  оценка  103  Uid!pthbj!csnvo!...
ключ 0x59  оценка   95  Wkf#rvj`h#aqltm#...
```
Верный ключ уверенно отрывается от остальных: ключи, отличающиеся на один бит, дают «почти текст» с заменёнными символами,
но оценка у них ниже.

## Флаг
`flag{demo_single_byte_xor}` (задание учебное, флаг публичный)

## Выводы / защита
- XOR с коротким ключом — это не шифрование: пространство ключей мало, а статистика языка выдаёт открытый текст.
- Для расшифровки с ключом в несколько байт (повторяющийся XOR, шифр Виженера) работает та же идея, но ключ ищут по частям:
  подбирают длину ключа (индекс совпадений / расстояние Хэмминга), затем решают задачу «один байт» для каждой позиции.
- В реальных системах используют проверенные алгоритмы (AES-GCM, ChaCha20-Poly1305) из проверенных библиотек
  и не придумывают собственные схемы.
